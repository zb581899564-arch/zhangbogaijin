# 疲劳一致的 FCLS–FCRS 左移/右移策略规范

版本：`fatigue-shift-v2-common-gap`  
正式模式：`LEFT_RIGHT`  
状态：P8.6 冻结实现  
适用范围：`deterministic_canonical`、FM0–FM3、HMOPSO-QGS-F、ZHANGBO-FULL、P8/P9 正式配置

## 1. 策略目的

传统左移或右移通常把工序看成长度固定的甘特条，直接改变其开始时间。但在本研究的疲劳感知调度中，工序开始时间一旦变化，会依次改变：

1. 工人的空闲恢复时间；
2. 工序开始时疲劳度；
3. 疲劳引起的动态加工与设置时长；
4. 工序完工时间；
5. 后续工序的机器、工人和工件前序可用时间；
6. 能耗、工人成本、疲劳指标及三个优化目标。

因此，本策略不允许简单平移甘特条。每个进入正式判断的左移或右移候选，都必须从完整调度状态重新传播恢复、疲劳、动态工时、能耗、成本和目标。

新策略由两个连续阶段组成：

- **FCLS（Fatigue-Consistent Left Shift）**：在机器与工人的共同空档中尝试提前工序；
- **FCRS（Fatigue-Consistent Right Shift）**：在左移完成后冻结全局完工期上界，通过有界右移增加恢复机会并改善 TEC 或 TWC。

执行顺序固定为：

```mermaid
flowchart LR
    S0["S0：基础 FM 调度"] --> L["一次正向 FCLS"]
    L --> S1["S1：左移后调度"]
    S1 --> C["冻结全局 CmaxStar"]
    C --> R["一次反向 FCRS"]
    R --> S2["S2：最终调度"]
```

每次解码只执行一次正向 FCLS 和一次反向 FCRS，不递归运行到固定点。

## 2. 符号与调度状态

对工序 $O_{j,k}$，记：

| 符号 | 含义 |
|---|---|
| $S_{j,k}$ | 工序开始时间 |
| $C_{j,k}$ | 工序结束时间 |
| $C^J_{j,k}$ | 同一工件前序工序的结束时间 |
| $C^M_{j,k}$ | 同一机器序列前驱的结束时间 |
| $C^W_{j,k}$ | 同一工人序列前驱的结束时间 |
| $S^M_{next}$ | 同一机器序列后继的开始时间；无后继时为 $+\infty$ |
| $S^W_{next}$ | 同一工人序列后继的开始时间；无后继时为 $+\infty$ |
| $F^{before}$ | 工人上一项任务结束后的疲劳度 |
| $F^{start}$ | 当前工序开始时、自然恢复后的疲劳度 |
| $F^{end}$ | 当前工序结束后的疲劳度 |
| $C_{max}$ | 当前调度的全局最大完工时间 |
| $C_{max}^{*}$ | 完成全部 FCLS 后冻结的全局最大完工时间 |
| $\varepsilon$ | 数值比较容差，默认 $10^{-9}$ |

工人身份必须由“工厂 + 工人编号”共同确定；机器身份必须由“工厂 + 阶段 + 机器编号”共同确定。

调度图同时包含三类有向约束边：

- 工件工艺前序边；
- 同一机器上的加工顺序边；
- 同一工人承担任务的顺序边。

任何候选图出现环、工件前序冲突、机器重叠、工人重叠或非法资源分配时，立即拒绝。

## 3. 统一的完整状态传播

FCLS 预检查和正式候选传播使用同一套单工序状态公式，防止“预估时长”和“正式解码时长”含义不一致。

### 3.1 最早开始时间

在给定调度图和可选释放时间 $R_{j,k}$ 下：

\[
S_{j,k}=\max\left\{R_{j,k},C^J_{j,k},C^M_{j,k},C^W_{j,k}\right\}.
\]

FCLS 中的 $R_{j,k}$ 取共同空档左边界；FCRS 中的 $R_{j,k}$ 取右移候选释放时间。没有额外释放约束时取0。

### 3.2 自然恢复

若工人上一项任务结束时间为 $C^W_{j,k}$，则任务间恢复时长为：

\[
t^{rec}_{j,k}=\max\left(0,S_{j,k}-C^W_{j,k}\right).
\]

在允许自然恢复的模式中：

\[
F^{start}_{j,k}=F^{before}_{j,k}
\exp\left(-\mu_{f,w,k'}t^{rec}_{j,k}\right),
\]

其中 $k'$ 是该工人上一项任务所属阶段。没有工人前序任务时，初始疲劳为0，且初始等待不计入“任务间自然恢复总时长”。

### 3.3 基础工时与疲劳动态工时

基础加工时间、基础设置时间和基础总占用时间分别为：

\[
PT^0_{j,k}=\frac{ST_{j,k}}{MS_{f,k,m}\,WE_{f,w}},
\]

\[
SET^0_{j,k}=\frac{SUT_{j,k}}{WE_{f,w}},
\]

\[
AT^0_{j,k}=PT^0_{j,k}+SET^0_{j,k}.
\]

疲劳倍率为：

\[
q_{j,k}=1+\frac{r_k}{\ln 2}\ln\left(1+F^{start}_{j,k}\right).
\]

实际加工、设置及总占用时间为：

\[
PT_{j,k}=q_{j,k}PT^0_{j,k},\qquad
SET_{j,k}=q_{j,k}SET^0_{j,k},
\]

\[
AT_{j,k}=PT_{j,k}+SET_{j,k},\qquad
C_{j,k}=S_{j,k}+AT_{j,k}.
\]

工序结束后的疲劳累积为：

\[
F^{end}_{j,k}=F^{start}_{j,k}+
\left(1-F^{start}_{j,k}\right)
\left(1-e^{-\lambda_{f,w,k}AT_{j,k}}\right).
\]

FM0 中疲劳值固定为0、倍率固定为1；FM1–FM3按各自是否允许恢复和疲劳感知选工的规则传播。左移/右移算法本身不另造一套疲劳公式。

### 3.4 能耗、成本和目标

每次完整传播都重新计算当前生产实现中的：

\[
EC_{j,k}=AT_{j,k}\,P_{f,k,m}+Idle^M_{j,k},
\]

\[
WC_{j,k}=\left(AT_{j,k}+Idle^M_{j,k}\right)Cost_{f,w}.
\]

其中待机单位能耗率在当前规范生产实现中固定为1。三个正式比较目标从七槽兼容载体读取：

```text
objective[0] = Cmax
objective[1] = TEC
objective[6] = TWC
```

## 4. FCLS：机器—工人共同空档左移

### 4.1 核心思想

一个工序只有同时获得机器和工人，才能真正提前。因此，FCLS不再单独寻找机器空档或工人空档，而是同时调整该工序在机器序列和工人序列中的插入位置，并寻找二者共同允许的可行时间区间。

允许以下三类候选：

1. 机器序列位置提前，工人序列位置保持不变；
2. 工人序列位置提前，机器序列位置保持不变；
3. 机器和工人序列位置同时提前。

不允许两个资源位置都保持不变，也不允许任何资源位置向后移动。

### 4.2 共同空档边界

对某个候选插入位置，共同空档左边界为：

\[
L=\max\left\{C^J_{j,k},C^M_{j,k},C^W_{j,k}\right\}.
\]

共同空档右边界为：

\[
U=\min\left\{S^M_{next},S^W_{next}\right\}.
\]

使用与完整传播相同的疲劳状态内核，在释放时间 $L$ 下预计算候选的开始时间与动态结束时间。只有满足：

\[
S'_{j,k}<S_{j,k}-\varepsilon,
\]

\[
C'_{j,k}\le U+\varepsilon
\]

的候选，才进入完整传播。

这里的“共同空档”并不要求机器和工人在完全相同的历史空档内同时空闲；它由工件前序、候选机器前驱、候选工人前驱以及两类资源后继共同确定。

### 4.3 候选顺序与数量上限

去除重复调度图后，候选按以下稳定顺序排列：

1. 预测开始时间更早；
2. 预测结束时间更早；
3. 机器插入槽编号更小；
4. 工人插入槽编号更小；
5. 调度图稳定指纹更小。

每道工序默认最多对前8个候选进行正式检查。预检查判定共同空档过短的候选只记录拒绝原因，不进行完整传播。

### 4.4 完整传播与接受规则

通过预检查的候选必须完整重传播整个调度图。候选同时满足以下条件时，接受该工序遇到的第一个候选：

1. 调度图无环；
2. 工件前序、机器互斥、工人互斥和资源合法域全部满足；
3. 该工序的实际开始时间严格提前：

   \[
   S'_{j,k}<S_{j,k}-\varepsilon;
   \]

4. 全局最大完工时间不恶化：

   \[
   C'_{max}\le C_{max}+\varepsilon.
   \]

FCLS不要求TEC和TWC同时不恶化。原因是疲劳、恢复和资源空闲结构变化可能引起TEC或TWC小幅波动；FCLS的职责是构造可行且不恶化工期的主动调度，最终多目标优劣仍由外层HMOPSO-QGS/PDDR机制处理。

每次接受后立即更新当前调度，再继续检查后续工序。因此，后一个工序看到的是前面已接受左移后的最新状态。

### 4.5 FCLS伪代码

```text
current = S0
按“阶段 → 开始时间 → 工件 → 工厂”的稳定顺序遍历工序o
    枚举o在机器序列和工人序列中的所有不向后插入组合
    丢弃两类位置都不变、产生环或重复指纹的组合
    计算共同空档[L,U]和疲劳一致的预览结束时间
    按稳定规则排序，最多保留8个
    对每个能够装入共同空档的候选
        完整重传播整个调度
        检查可行性、实际提前和Cmax不恶化
        若通过：接受第一个候选并更新current，停止本工序搜索
S1 = current
```

## 5. FCRS：冻结全局 CmaxStar 的有界右移

### 5.1 冻结全局工期上界

完成整轮FCLS并得到 $S_1$ 后，只冻结一次：

\[
C_{max}^{*}=C_{max}(S_1).
\]

后续无论接受多少个右移候选，$C_{max}^{*}$ 都保持不变。这里使用的是所有工厂共同的全局最大完工时间，不是单个工厂的完工时间。

### 5.2 右移上界

FCRS不改变工序的工厂、机器、工人，也不改变工件、机器和工人序列。它只为目标工序增加一个释放时间约束。

对工序 $O_{j,k}$，先在当前调度图中求：

\[
LFT_{j,k}=\min\left(C_{max}^{*},\min_{v\in Succ(j,k)}S_v\right),
\]

其中 $Succ(j,k)$ 包含工件、机器和工人序列上的直接后继。基于当前实际工时，最大候选开始时间为：

\[
S^{upper}_{j,k}=LFT_{j,k}-AT_{j,k}.
\]

初始建议右移量为：

\[
\Delta_0=S^{upper}_{j,k}-S_{j,k}.
\]

若 $\Delta_0\le\varepsilon$，该工序没有可用右移空间。

### 5.3 最多10次确定性减半回退

FCRS按当前调度图的反向拓扑顺序处理工序。对存在右移空间的工序，依次尝试：

\[
\Delta_a=\frac{\Delta_0}{2^a},
\qquad a=0,1,\ldots,9.
\]

相应释放时间为：

\[
R^{(a)}_{j,k}=S_{j,k}+\Delta_a.
\]

每次尝试都完整重传播整个调度。最大右移提议失败后，不随机调整，而是严格减半；最多10次，首次接受后停止该工序的回退搜索。

注意：动态工时会随恢复和疲劳变化，因此实际接受右移量不一定等于提议右移量。事件日志同时记录`proposalShift`和`acceptedShift`。

### 5.4 FCRS接受规则

右移候选必须同时满足：

1. 调度保持可行；
2. 目标工序实际开始时间严格推迟：

   \[
   S'_{j,k}>S_{j,k}+\varepsilon;
   \]

3. 不突破左移后冻结的全局工期：

   \[
   C'_{max}\le C_{max}^{*}+\varepsilon;
   \]

4. TEC不恶化：

   \[
   TEC'\le TEC+\varepsilon;
   \]

5. TWC不恶化：

   \[
   TWC'\le TWC+\varepsilon;
   \]

6. TEC和TWC至少有一项严格改善：

   \[
   TEC'<TEC-\varepsilon
   \quad\lor\quad
   TWC'<TWC-\varepsilon.
   \]

其中TEC、TWC的比较对象是处理该工序前的当前调度，而不是固定与最初的 $S_1$ 比较。接受后立即更新当前调度，再处理下一个反向拓扑工序。

### 5.5 FCRS伪代码

```text
current = S1
CmaxStar = Cmax(S1)     // 只冻结一次
按当前调度图的反向拓扑顺序遍历工序o
    根据CmaxStar和o的全部直接后继求最大右移量Delta0
    若Delta0 <= epsilon：跳过
    for attempt = 0..9
        delta = Delta0 / 2^attempt
        只为o增加releaseOverride = oldStart + delta
        保持全部资源及三类顺序不变
        完整重传播整个调度
        若实际右移、Cmax<=CmaxStar、TEC/TWC均不恶化且至少一项严格改善
            接受候选并更新current
            break
S2 = current
```

## 6. FCLS与FCRS的职责差异

| 对比项 | FCLS | FCRS |
|---|---|---|
| 遍历方向 | 稳定正向顺序 | 反向拓扑顺序 |
| 主要目的 | 利用机器—工人共同空档提前工序 | 在不增加工期的条件下增加恢复并降低TEC或TWC |
| 是否改变资源 | 不改变资源身份 | 不改变资源身份 |
| 是否改变机器/工人顺序 | 可以把目标工序插入更早槽位 | 完全冻结 |
| 候选控制 | 每工序最多8个稳定候选 | 每工序最多10次减半回退 |
| 工期门 | 相对当前调度不恶化 | 不超过冻结的全局 $C_{max}^{*}$ |
| TEC/TWC门 | 不作为接受硬门 | 均不恶化，且至少一项严格改善 |
| 动态状态 | 每个正式候选完整重传播 | 每次回退候选完整重传播 |

## 7. 完整传播与jMetal FE口径

FCLS/FCRS内部的完整传播虽然会重新计算整个调度，但它属于一次粒子评价内部的确定性解码细化，不创建新的优化算法候选解，因此：

```text
一次外部 problem.evaluate(solution) = 1 jMetal FE
该评价内部的FCLS/FCRS完整传播 = 0额外jMetal FE
```

内部传播次数必须独立记录：

```text
internalPropagations = leftFullRecomputations + rightFullRecomputations
```

这样既能保证不同算法使用相同jMetal评价预算，又能单独审计新解码策略带来的真实计算开销。内部传播次数、FCLS/FCRS耗时和Decoder总耗时不得混写成FE。

## 8. 确定性、日志与拒绝原因

正式实现使用稳定遍历、稳定排序、固定候选上限和确定性减半回退，不在FCLS/FCRS内部引入新的随机数。

每个候选事件至少记录：

- 阶段`FCLS/FCRS`；
- 工件、阶段、机器槽、工人槽；
- 共同空档左右边界；
- 移位前后开始时间、疲劳度、动态时长和结束时间；
- 移位前后Cmax、TEC、TWC；
- 冻结的`CmaxStar`；
- 提议右移量、实际接受右移量和回退次数；
- 是否接受及明确拒绝原因。

主要拒绝原因包括：

```text
DAG_CYCLE
COMMON_GAP_TOO_SHORT
NOT_EARLIER
CMAX_WORSE
NOT_LATER
CMAX_STAR_EXCEEDED
TEC_WORSE
TWC_WORSE
NO_TEC_TWC_GAIN
JOB_PRECEDENCE_VIOLATION
MACHINE_OVERLAP
WORKER_OVERLAP
INVALID_RESOURCE_ASSIGNMENT
```

事件、S0/S1/S2调度和评价轨迹均生成SHA-256，便于确认后续性能优化没有改变算法行为。

## 11. 与旧版策略的关键区别

旧版存在四个关键问题：

1. 要求机器槽和工人槽必须同时提前，遗漏一个资源位置不变的合法共同空档；
2. FCLS使用三目标Pareto-safe门，错误拒绝Cmax不恶化的真实左移；
3. FCRS使用工厂完工时间，而不是FCLS后冻结的全局`CmaxStar`；
4. FCRS没有强制TEC或TWC至少一项严格改善。

`fatigue-shift-v2-common-gap`已经覆盖这些旧规则。历史v1结果只保留作来源证据，不得与当前S0/S1/S2结果混写。

## 12. 论文方法章节推荐表述

论文中可使用以下表述：

> 为避免传统固定工时移位在疲劳感知环境中造成状态不一致，本文设计了疲劳一致的左移—右移策略。首先，FCLS同时考虑工件前序、机器序列和工人序列，在机器—工人共同空档内生成提前候选；候选经完整状态传播后，仅在调度可行、目标工序实际提前且全局最大完工时间不恶化时接受。随后，以FCLS所得调度的全局最大完工时间为固定上界，FCRS按反向拓扑顺序尝试右移工序；若最大右移候选不可接受，则最多执行10次确定性减半回退。FCRS仅接受不突破冻结工期、TEC与TWC均不恶化且至少一项严格改善的候选。每个候选均重新传播自然恢复、疲劳累积、动态加工与设置时间、能耗、工人成本及目标函数。上述内部传播属于单次解码过程，不额外计入jMetal函数评价次数，但单独记录传播次数与运行时间，以保证算法预算比较和计算成本审计的公平性。

论文中不得写成：

- “直接把工序条向左或向右平移”；
- “右移后工时保持不变”；
- “FCLS保证三个目标同时改善”；
- “每次内部传播都增加一次FE”；
- “右移使用各工厂自己的Cmax”；
- “重复左移右移直到不能再改善”。
