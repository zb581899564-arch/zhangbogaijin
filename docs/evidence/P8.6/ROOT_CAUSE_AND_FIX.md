# P8.6 根因与修复映射

## 修改前根因

1. FCLS 同时要求机器槽和工人槽都提前，遗漏“一个资源提前、另一个保持原槽”的合法共同空档。
2. FCLS 使用三目标 Pareto-safe 接受门，错误拒绝了 Cmax 不恶化但 TEC 或 TWC 小幅波动的合法左移。
3. FCRS 使用工厂完工时间而非左移后冻结的全局 `CmaxStar`。
4. FCRS 沿用三目标统一接受门，没有强制 TEC/TWC 至少一项严格改善。
5. 事件证据缺少共同空档边界、冻结 Cmax、proposal/accepted shift 和回退次数。

## 当前实现

- 语义版本：`fatigue-shift-v2-common-gap`。
- FCLS允许机器或工人其中一个序列位置保持不变；候选必须至少在一个资源序列上提前。
- 共同空档为机器、工人及工件前序可用区间的交集；预检查和完整传播共用同一单工序状态内核。
- 每道工序稳定排序后最多完整传播8个FCLS候选；接受门仅为开始更早、调度可行、Cmax不恶化。
- FCLS完成后冻结全局`CmaxStar`。
- FCRS不改变任何资源与序列，只增加`releaseOverride`；最大proposal失败后最多执行10次确定性减半回退。
- FCRS接受门为Cmax不超过`CmaxStar`、TEC/TWC均不恶化且至少一项严格改善。
- 每个候选完整重传播全部下游疲劳、动态工时、能耗、成本和七槽目标；内部传播不增加jMetal FE。
- 固定只执行一次正向FCLS和一次反向FCRS，不递归求固定点。

## 证据边界

- I1/X0在当前语义下真实产生FCLS和FCRS事件，可作为论文公开图例。
- 用户批准后使用固定seed重新筛选I0四向量；新版I0/X0通过“一左一右”演示门：FCLS为`1/6`接受、FCRS为`1/41`接受、内部完整传播为42次。
- I0筛选只公开四向量和事件数量，没有输出程序时间、目标、疲劳轨迹或甘特答案；数值答案继续锁定到用户本人提交手算副本SHA-256之后。
- P8.6已完成；I0本人手算—程序逐项核对仍作为独立后续验收门。
