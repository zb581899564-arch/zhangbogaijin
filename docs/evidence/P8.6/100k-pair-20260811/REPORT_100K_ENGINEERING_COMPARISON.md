# P8.6 100k FE 双算法工程比较完整报告

## 1. 结论摘要

本次运行得到一个值得继续验证的工程信号，但还不是正式论文结论。

- `ZHANGBO-FULL` 与 `HMOPSO-QGS-F` 均在 `20_2_3_1`、seed `20260808`、population `100` 下完成 `100000 FE`。
- 两条路径使用相同实例、SUT、疲劳参数、FM3 解码、`LEFT_RIGHT` 移位语义和初始四向量种群；初始种群 SHA-256 完全一致。
- FULL 的 HV、IGD、Spacing、非支配解数量和覆盖关系明显占优；TEC、TWC 最优值也更低。
- 基线的最优 Cmax 更低；FULL 的多数疲劳强度指标反而更差，仅工人最终疲劳方差更低。
- FULL 比基线慢约 `9.56%`，不是早期旧版本出现的 35 倍时间差。
- 两次运行均无非法解、无 CFVF repair，评价预算精确闭合。

必须醒目标记的限制：本次 Runner 实际使用 `Q_Times=2`、`LS_Times=1` 的工程参数，而非论文正式口径的 `50/30`。因此本报告只能称为“当前规范语义下的 100k 工程比较”，不能称为“李明哲 HMOPSO-QGS 正式复现比较”。

综合判定：`PROMISING_ENGINEERING_SIGNAL_WITH_FORMAL_BASELINE_BLOCKER`。

## 7. Reference、HV和IGD审计

本次自动报告的reference是“当前FULL与BASE两次运行的最终前沿并集，再做严格Pareto过滤”，共293点。独立重算确认：

- 保存的reference与严格非支配并集逐点完全一致；
- FULL贡献230点，BASE贡献63点，无共享点；
- FULL占reference的78.5%；
- 独立计算的IGD、Spacing、双向C-metric与Java输出一致；
- 归一化边界来自该pair reference，HV固定参考点为归一化空间的1.1。

因此数值计算没有发现程序错误，但reference构造对FULL高度内生。IGD从0.1321降到0.0508这一差距可作为本次pair诊断，不能作为正式论文证据。

正式实验必须先冻结统一reference：同实例全部纳入比较的算法、全部正式运行前沿合并后做非支配过滤，并让所有算法共用固定归一化边界和HV reference point。还应补充leave-one-run-out或外部参考前沿敏感性分析。

## 8. 阻断项与旧自动报告纠正

旧自动报告文件名和标题写成“500000 FE”，但两条记录实际都是100000 FE。这是报告模板错误，不能沿用。

更重要的是，配置文件明确记录：

```text
qTimes=2
localSearchTimes=1
```

而论文正式参数应为：

```text
Q_Times=50
LS_Times=30
```

其余主要概率已按当前正式设置记录，例如随机系数上界0.6、交叉率0.2/0.5/0.5、变异率0.08/0.15/0.25。循环参数不一致仍足以阻止将该基线称为严格正式HMOPSO-QGS-F结果。

这不是“结果无效”：它仍能证明当前代码链路、机制触发、预算、输入公平性和工程信号；但它不回答“在李明哲正式论文参数下，FULL是否仍然占优”。

## 9. 当前可以和不可以得出的结论

可以说：

1. 两条当前工程配置均能稳定跑到100000 FE，前沿非空，预算闭合，无非法解和异常repair。
2. FULL的全部批准创新机制真实触发。
3. 在这一次工程配置下，FULL的HV、IGD、Spacing、TEC、TWC和前沿覆盖表现出明显优势信号。
4. FULL相对基线的时间开销约为9.56%，不再是数量级膨胀。
5. FULL没有在最优Cmax和多数疲劳诊断指标上全面胜出。

不可以说：

1. 已正式复现李明哲论文实验。
2. FULL在统计意义上显著优于基线。
3. 当前IGD/HV可直接进入论文最终表格。
4. 当前疲劳机制使所有疲劳指标都更优。
5. 已通过当前语义下的100k性能门或可直接启动20次正式矩阵。
