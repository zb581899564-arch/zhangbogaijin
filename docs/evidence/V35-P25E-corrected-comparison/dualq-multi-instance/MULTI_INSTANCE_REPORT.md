# gBlockLength=15 多实例验证报告（gb5 vs gb15）

- 日期：2026-08-16
- 目的：验证 dualQ 分块冻结中 gBlockLength 单变量从 5 调到 15（Qg TD 更新 2000→2800）的收益是否为实例依赖。若 gb15 在多个代表实例上与 20_2_3_1 方向一致且无实例明显退化，则批准 gb15 转正进正式配置；否则维持 gb5。
- 判定标准（预先承诺）：不要求每项指标都赢，要求**没有任何实例出现明显退化**（IGD/HV 显著变差）。

## 实验设计

| 项 | 值 |
|---|---|

## 结论：gb15 不转正，正式配置维持 gb5

1. **收益是实例依赖的，且随规模呈倒 U 型**：10/20 实例上 gb15 改善 IGD/Cmax/TEC（HV 打平或略升），50 实例完全打平，100 实例 HV −11.4%、IGD +32.1% 明显退化。按预先判据（不允许任何实例明显退化），gb15 **不满足转正条件**。
2. **机制解释**：gBlock 从 5 增至 15 让 Qg 在每个 G 块内学得更久（TD 2000→2800），全局搜索更充分地压向占优方向。小实例（10/20 工件）Q 表状态空间小，学习充分，收益真实；100 工件状态空间大，固定 2800 次 TD 更新覆盖不足，长 G 块反而把 swarm 过久锁定在全局方向，压制 P 块局部多样性，TEC/TWC 维度均衡受损（IGD +32% 即收敛不全面）。Cmax 在所有实例上持平或改善（10: −1.0%、20: −2.0%、50: −0.1%、100: −2.6%），佐证了"更长的 G 块强化 Cmax 方向"的机制定位。
3. **正式配置决策**：dualQ 分块冻结维持 P24.2 冻结值（warmup=0.10, P-block=5, G-block=5）。`gBlockLength` 保留为实验参数（`ZhangBoDualQCoordinationConfiguration.blockFrozen(warmup, blockLength, gBlockLength)`），供论文消融或实例级调参使用，不进入 Table-9 正式口径。
4. **对 500k A4 vs QGS 均势的补充结论**：此前 20_2_3_1 上 gb15 补足 Qg 学习（TD 2000→2800）后 4 seed 全面优于 QGS 基线，曾提示"500k 下 A4 与 QGS 差距源于 dualQ 冻结削减 Qg 学习"。多实例验证表明这一机制改善只在 Q 表可充分学习的实例上成立，作为全局配置不可行。500k 下 A4 与 QGS 的均势维持原判：机制差异（dualQ 冻结 vs 同步双 Q）而非缺陷，正式报告按 gb5 口径如实呈现。
