## 结论

Q-pbest已作为显式开关接入李明哲作者Java直接派生主线。P6.3启用时，四个子群各维护一张`16×4` Qp表，从本谱系容量6档案中通过KEEP、DIRECTIONAL、EPSILON和COMPLEMENTARY选择个人领导，再把该领导送入CFVF认知项。原Q-gbest仍按P6.0机制正常选择和学习，因此本阶段是同步学习消融，不是最终分块冻结双Q版本。

Qp关闭时不构造控制器、不初始化Q表、不消耗Qp随机事件，旧配置规范文本不增加Qp字段；现有B3兼容测试继续通过。P6.4预热、P/G-block冻结以及P7机制均未实现。

## 实现契约

- 配置仅在`QP_LINEAGE_ARCHIVE`模式下启用；构建时强制要求非零P5疲劳参数、原Qg、CFVF、评价后PDDR和谱系档案；
- 四表零初始化，`alphaP=0.30`、`gammaP=0.80`，探索率按已消耗FE从`0.30`线性降至`0.05`；
- 状态为`4*(2H+R)+E`，首代E取3，停滞门槛3代，冗余阈值为`max(0.80,有效余弦中位数)`；
- 互补动作使用总体v2阈值质量集合`phiG<=phiBest+0.15`，质量不足、社会方向为零或个人方向不可计算时屏蔽；重复动作只保留较小编号；
- 奖励为`2*rDom + deltaPhi + 0.5*IArchive + 0.25*deltaRisk`，在后代唯一一次疲劳评价后、PDDR及任何局部搜索前计算；
- 档案贡献由无副作用分支预演得到，只有PDDR保留分支才真正提交档案；
- 每群冻结旧Q表，按稳定分支ID聚合TD目标并在批末一次提交；无效下一动作不进入`maxQ`；
- 档案条目恢复领导只覆盖`JS/FA/MA/WA`和已有目标槽，不解码、不增加FE、不修改模板或档案快照；作者扩展WA后续阶段块保持不变。

## 关键校正

作者四子群可以让同一来源粒子在一代内派生到多个群。若只以旧`lineageId`保存Qp选择，后写入的群会覆盖前一分支。本阶段为每个群槽位分配不可变`branchId`，用它闭合“选择—CFVF后代—奖励”转移；PDDR之后再按P6.2规则重建谱系并确定性继承或回退个人领导。
